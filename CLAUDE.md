# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

## What this is

Value Constellation maps where participants in a meeting stand relative to each
other, from the transcript. One Next.js app: paste a transcript, get a 2D map
where each speaker is a position with a region, and every coordinate traces back
to a verbatim line.

`README.md` covers the pipeline, the design commitments, and what real-transcript
testing showed. Read it before changing behaviour — several of the constraints in
this codebase exist because a specific misreading was observed.

## Architecture

```text
app/page.tsx              overview: the example gallery, reading guide, region
                          rule, limits
app/new/page.tsx          the composer, on its own page
app/studio/page.tsx       the tool: console rail, plate, inspector
app/how-it-works/page.tsx reference: models, thresholds, data handling
app/api/analyze/route.ts  request handling only
lib/analyze.ts            the pipeline, shared with the fixture builders
lib/models.ts             the two model names; no imports, so clients can read them
lib/                      all logic, no React, no server-only imports
components/               presentation; components/landing/ is overview-only
data/                     example transcripts and a precomputed fixture
docs/hero.svg             generated by scripts/render-hero.ts
archive/                  frozen v1 Python value-vector pipeline — do not extend
```

The two pages have different jobs and different rules. The overview explains and
is read once; the studio works and is used for an hour. Display type, scroll
reveals and long prose belong on the overview only — the studio's four sizes
between 12 and 15px are correct for a dense working surface. Twelve is the
floor on both pages: 11px of Hangul costs more to read than the control it
labels saves.

`lib/` is deliberately free of React and of anything Node-only, so the same
modules run in the browser, in the API route, in the test runner, and in the hero
renderer. `parseTranscript` runs client-side for the composer preview and
server-side for the real analysis, from one implementation — keep it that way
rather than adding a second, looser approximation.

## Commands

```bash
npm run dev        # http://localhost:3000
npm run build      # production build; also typechecks
npm test           # node --test over lib/*.test.ts, no model calls
npm run typecheck  # tsc --noEmit
npm run hero       # redraw docs/hero.svg after changing map geometry
npm run hero:data  # re-analyse the English hero transcript (costs an API call)
npm run fixtures   # rebuild the four examples through the pipeline (costs money)
```

Requires Node 22.6+ for native type stripping in the test runner.
`OPENAI_API_KEY` goes in `.env.local`, server-side only, never `NEXT_PUBLIC_`.

## Conventions

**Honesty over polish.** This tool draws conclusions about real people from
sparse data. When a figure is not evidence, say so on the map rather than in a
tooltip: saturated fits, attribution at or below chance, transcripts too thin to
judge at all, positions from fewer than three statements, and speakers who could
not be placed are all surfaced already. Do not add a progress bar for a server
that reports no progress, and do not print an absolute projected distance — they
mean nothing across two maps, so every distance on the page is a share of the
widest gap.

**A layout may not grade itself.** Attribution and separation are computed in
embedding space, before any projection, and all three layouts report identical
numbers — `lib/fixtures.test.ts` pins this. The default layout is fitted to push
the speakers apart, so measuring "the speakers are far apart" on its output would
be circular; it read more than twice as high when it was measured there. Any new
diagnostic goes in `lib/aggregate.ts` alongside these, not in a component with
access to coordinates.

**A figure needs a name and a sentence.** Every number on screen is shown with
a plain-language label and one line saying how to read it, and the reader gets
the verdict before the arithmetic that produced it. Three coinages and four bare
numbers under a map — `발언 되찾기 64% / 25%` — is not transparency; it is noise
in the shape of transparency. Distances lead with a phrase and follow with the
ratio, never the other way round. Where a threshold decides what the sentence
says, that decision lives in `lib/aggregate.ts` with the metric, not in the
component that renders it and not copied into `scripts/`.

**A summary must be checkable.** Per-speaker summaries come from the transcript,
never from the coordinates, so they read the same under every layout. They carry
the ids of the statements they rest on, an id the speaker did not say is dropped
rather than shown, and the interface marks those statements in the list.

**Colour means a person.** The eight speaker hues are the only saturated colour
in the interface. Buttons, selection, focus and warnings are ink on paper, and
the overview changes gravity with an inverted band rather than a hue. A "brand
accent" would read as somebody's identity colour.

**The mono face has no Hangul.** `--font-plex-mono` is for digits and Latin
identifiers only. Any Korean string set in it silently falls back to a system
font. Labels get their texture from size, weight and tracking instead.

**Strings live in `lib/i18n.ts`.** Both languages, always, including `title`
hints — those are exactly what a first-time Korean reader needs. Transcript
content is never translated; the inspector shows a translation beside the
original, not in place of it. The overview's prose lives in `lib/landing.ts`
instead, so forty control labels do not end up buried inside an essay.

**Nothing on the map is tuned.** The region's shape follows from one measured
quantity — the median distance from a statement to the nearest other one by the
same person, pooled across speakers — and the
overview publishes that rule to the reader. A constant chosen because the
picture looked better with it cannot be defended to somebody who disagrees with
what the picture says about them, so if a shape needs fixing, change what is
measured rather than adding a multiplier.

**Tests pin observed failures.** Every case in `lib/*.test.ts` is a format or
failure mode seen in real data. Tests must not call a model. When fixing a bug in
parsing, projection, regions or distances, add the case that produced it.

**Fixtures are committed output.** `data/fixtures/precomputed.json` lets the app
open on a finished map with no API key. Regenerate it deliberately, not casually.

## Working notes

- Prefer editing `lib/` and letting components stay thin.
- Map geometry lives in `lib/frame.ts` (the drawing frame) and `lib/blob.ts`
  (speaker regions). Both are shared with `scripts/render-hero.ts`; run
  `npm run hero` when either changes, or the README image drifts from the app.
- `archive/2026-value-vector-pipeline/` is the previous generation: a Python
  pipeline for 19-dimensional signed Schwartz value vectors. It is frozen. Its
  findings are documented in its own README; do not run or extend it as part of
  work on the current app.
- Do not commit `.omc/`, `.env*`, `*.mp3`, `node_modules/`, `.next/`, or model
  caches.
